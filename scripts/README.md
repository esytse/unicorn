# Repository integrity checks (#335 / #341)

Run locally with `python3 -m unittest discover -s scripts -p 'test_*.py' && python3 scripts/repo_integrity.py`. The existing **Research governance** PR job runs both commands. Tests copy the corpus to a temporary directory, deliberately corrupt one invariant at a time, assert a useful diagnostic, and leave the checkout green.

`repo_integrity.py` checks internal Markdown targets; the explicit canonical map and its live authority; portfolio/ranking references; required as-of metadata on the three governance audits; declared supersession and derived upstream paths; optional upstream SHA-256 freshness pins; prediction/outcome case and candidate keys; and pinned SHA-256 hashes for every file in the frozen #261 corpus. The `frozen-261.json` manifest records the unchanged `main` baseline at #342. Changing the manifest deliberately requires separate review; never regenerate it to hide a #261 change.

GitHub issues remain authoritative for queue state. CI cannot query a moving issue queue deterministically. The optional `scripts/issue-state.json` export, if present, is checked for required metadata and READY/RUNNING/WAITING/BLOCKED trigger/dependency contradictions. Its fixture is tested without committing a potentially stale live issue snapshot. Derived SHA pins are enforced only where a document declares `Canonical upstream` and `Upstream SHA-256`; no blanket date expiry is inferred from a document edit. The explicit as-of requirement applies to the three governance audit documents pending #340's broader metadata policy.

Prospective T0 and checkpoint records under `research/prospective/` use the same runner. On a PR, pass `--base-ref <base-sha>` to reject edits/deletions of committed records and replacement of prior version/seal entries. A local seal detects accidental T0 changes; the base comparison prevents replacing both T0 and its seal. Checkpoint dates, parent joins, required fields and benchmark arithmetic are checked. The PR workflow passes its base SHA automatically.

`performance.py` adds #329 scorecards to the sealed prospective records. Each checkpoint needs an append-only supplement with stable issuer/security identifiers, lifecycle and corporate-action treatment, a sourced complete adjusted wealth series or explicit DATA-LIMITED reason, dated event evidence and available cash/competing-candidate comparators. Integrity checks verify return/drawdown arithmetic and matching windows. Run `python3 scripts/performance.py` to print the currently filed scorecards; an empty list means there are no prospective observations yet, not that performance has been validated.

`discovery_coverage.py` validates #330's canonical coverage ledger: every architecture-first lane has exactly one explicit search outcome, bounded searched families, source files and rescan triggers. It also ensures active/no-capture/rejected states do not contradict their candidate lists and that the familiarity audit still partitions the live ranking's top 20. The checker validates repository consistency, not the truth or completeness of the underlying research evidence.

`objective_ranking.py` validates #356's bounded 65-company dual-axis inventory. It requires unique continuous structural and capital ranks, reconciles key live monitor states, and prevents governed ACTION candidates from being silently placed below non-actionable comparators in the March-2028 capital order. Its negative tests deliberately corrupt membership, ordering, monitor state and axis disclosure.

`portfolio_feasibility.py` validates #357's probability-free portfolio constructions. It reconciles initial/staged weights, explicit cash, company ceilings, bear/base/upside values, two-failure stresses, transaction rules, live states and the exact £80k/£120k/£160k/£200k hurdle classifications. Negative fixtures prove that arithmetic, ceiling, rule and classification drift fails CI.
