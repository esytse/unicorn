# Workflow, permissions and agent execution economics

**Lifecycle:** CANONICAL discovery evidence
**As of:** 2026-10-09
**Issue:** #368
**Decision:** no new Gate-E company promotion; four listed benchmarks screened.

**Thesis chain:** abundant agents → constrained trusted authorization → controlled execution and audit/release gates → paid workflow/identity capture → valuation-aware allocation. The scarcity is permission to act and proven outcomes, not token generation.

**FACT:** [Microsoft Entra authorization documentation](https://learn.microsoft.com/en-us/entra/agent-id/authorization-agent-id), updated 12 June, describes delegated/application access, explicit consent, blocked powerful permissions and inheritable grants. This embeds agent controls in incumbent identity. Documentation is evidence of architecture, not standalone revenue. Retrieved 9 Oct.

**INTERPRETATION:** identity control and workflow switching costs can be durable, but each boundary has competition. Authorization tokens do not establish rights to reuse customer data. Audit logs can be open/portable; incumbent connectors and private cross-app execution vendors can bundle the gate. MCP/OAuth connectivity is a substitute for proprietary integration friction, while approval/liability and regulated release remain harder to standardize. Private orchestration providers are benchmarks, not a reason to buy a weaker listed proxy.

**Negative result:** no separately priced, company-material merchant permission/release-gate franchise with verified agent-specific renewal/retention/cash economics was found. No current prices or scenario returns are asserted for these discovery-only benchmarks; the valuation gate therefore remains explicitly untested, never passed.
